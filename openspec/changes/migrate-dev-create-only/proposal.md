# Proposal: `migrate dev --create-only` (Plan/Apply Separation)

Change: `migrate-dev-create-only` (Road to 1.0, Phase 3, epic "Introspection — `indigodb db pull`", task 6/8). One focused slice, not the epic.

## Context

`main` is clean at `9d6ea6d`; tasks 1/8–5/8 are merged and pushed. The archived 6/8 framing (Engram #671) reads: *"Plan/apply separation — divide migration execution into pre-flight and commit phases."* That wording is confirmed and **matches** the exploration's narrow reading: it demands a phase split, not arbitrary-revision diffing. `migrate deploy` already owns a real pre-flight (checksum, advisory lock, destructive scan) and a commit; `migrate dev` has none — so the split is needed only on the `dev` side.

## Intent

`migrateDev` (`packages/cli/src/migrate-runner.ts:312`) is one atomic run: resolve prev → plan → gate → write `migration.sql` → **immediately** apply → insert history → `COMMIT` → `saveSnapshot`. There is no way to see or review the generated SQL without mutating the database. `db push` has `--print`; `migrate dev` has no equivalent (`packages/cli/src/index.ts:147-158` — only `-n`, `-s`, `--force`).

## Scope

### In Scope
- `--create-only` flag on `migrate dev`, threaded as `DevOptions.createOnly?: boolean`.
- Pre-flight phase (unchanged): connect, `ensureHistory`, `resolvePrevSchema`, `planMigration`, diagnostics refusal, destructive `--force` refusal, write `migrations/<ts>_<name>/migration.sql`.
- Commit phase (skipped under `--create-only`): `applyMigrationSql`, history `INSERT`, `COMMIT`, `saveSnapshot`.
- Distinct, greppable success line, e.g. `✅ Migration created (not applied): <id>`.
- Tests in `packages/cli/test/migrate-runner.mjs` asserting the file is written and no apply/history/snapshot side effect occurs.

### Out of Scope
- Task 7/8 (history table / recovery verbs) and 8/8 (transaction-boundary control).
- A `prisma migrate diff`-style arbitrary two-state / offline comparison command.
- Any change to `planMigration`, `renderMigrationSql`, `migrateDeploy`, `migrateStatus`, or the 3/8–5/8 gates.
- Making `migrate dev` work without a database: shadow-replay still reads `_indigo_migrations` from the real target, so `--create-only` still connects. This is a documented divergence from Prisma.

## Capabilities

### New Capabilities
- `migration-plan-apply-separation`: pre-flight vs. commit phase boundary in `migrate dev`, `--create-only` semantics, side-effect contract, hand-off to `migrate deploy`.

### Modified Capabilities
- None.

## Approach

Split `migrateDev`'s existing linear body at the already-natural seam (after `writeFileSync`, before `applyMigrationSql`) and return early when `createOnly` is set. Purely additive control flow; the generated bytes are identical either way, so a `--create-only` file is picked up unchanged by a later `migrate deploy`.

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| Users expect an offline/no-DB dry run | Med | Explicit flag help text + spec scenario; connection is still required |
| Un-applied file leaves `.snapshot.json` stale, so the next `dev` re-diffs the same change | Med | Prev resolution is shadow-replay by default, which reads recorded history, not the snapshot; spec must pin this behavior |
| Scope creep into arbitrary-revision diffing | Med | Explicitly out of scope; would need its own exploration |

## Rollback Plan

1. Remove the `--create-only` CLI option and `DevOptions.createOnly`.
2. Delete the early-return block — `migrateDev` returns to its atomic path.
3. No schema, on-disk migration, or history-format change; no persisted state.

## Dependencies

- None beyond `main` at `9d6ea6d` (tasks 1/8–5/8 shipped).

## Success Criteria

- [ ] `migrate dev --create-only -n x` writes `migrations/<id>/migration.sql` and applies nothing
- [ ] No row is inserted into `_indigo_migrations`; `.snapshot.json` is untouched
- [ ] `migrate status` then reports that migration as pending, and `migrate deploy` applies it
- [ ] Diagnostics and destructive-without-`--force` still refuse before any file is written
- [ ] Plain `migrate dev` behavior is byte-identical to today
- [ ] `pnpm build`, `lint`, `test` and `cd crates && cargo test` stay green
